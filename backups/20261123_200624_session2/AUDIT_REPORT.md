## 2. Verified definitions (as implemented in the starter)

### 2.1 Network
- 1000 nodes, IDs 0..999, all present in the edge list; 7500 **unique directed
  arcs** (one row = one directed arc). No self-loops. 4 reciprocal arc pairs exist.
- Construction: undirected Barabási–Albert-style preferential-attachment backbone
  (`m = 7500 // 1000 = 7`, seed complete graph on 8 nodes), grown to 6972 unique
  undirected pairs; 528 random undirected pairs added to reach 7500 undirected
  pairs; each pair randomly oriented (50/50); a final random-directed-arc fill
  loop runs only if orientation created a collision. Result: 7500 arcs.
- Edge count semantics: **7500 directed arcs, which here is also 7500 underlying
  unordered node pairs** (each pair oriented once) with the exception of 4 extra
  reciprocal arcs added by the fill loop. This dual meaning is documented, not
  silently reinterpreted.
- Signs: `P(positive) = 0.5`; magnitude `U{1..10}`; `rating = ±magnitude`.
- Probability mapping: magnitude 1–3 → 0.1; 4–7 → 0.5; 8–10 → 0.9.
  Verified on file: 2278 / 2950 / 2272 edges in the three classes; 3720 positive,
  3780 negative; all `rating == polarity * strength`.
- Seed 42 regenerates the **byte-identical** CSV (checked with `pandas.equals`
  and a second independent generation). SHA-256 of the CSV:
  `659d4fa65a3904c96e5653c16f3357b95a43a00440844157b203eb0d3e3087b5`.
- Degree summary on file: out-degree 1–77 (mean 7.52), in-degree 1–67 (mean 7.50),
  no isolated nodes (998 distinct sources, 1000 distinct targets).

### 2.2 Diffusion model (C++ implementation, the only executable authority)
Synchronous, discrete rounds; per-node states:
`0 ignorant, 1 A-spreader, 2 B-spreader, 3 A-stifler, 4 B-stifler`.
1. Seeds A/B are initialized as spreaders; A/B seed overlap is rejected.
2. Each round, every current spreader selects **one uniformly random outgoing
   neighbor that it has not contacted before** (per-edge contact memory).
3. If it has no uncontacted outgoing neighbor, or the chosen target is not
   ignorant at the start of the round, the spreader becomes a stifler of its own
   rumor.
4. Otherwise, with the edge transmission probability, it sends its rumor; on a
   negative edge the rumor is flipped (A→B, B→A).
5. Proposals are resolved **synchronously**: the highest `strength` (= rating
   magnitude) wins; ties between different rumors are broken uniformly at random.
6. Final `spread_A` = count of states 1 and 3 (all ever-A nodes), likewise for B;
   `ignorant` = state 0; `rounds` = number of rounds executed.

This is a finite-contact Maki–Thompson variant (each spreader tries each out-edge
at most once). It matches the starter README's "one-contact-per-neighbor"
statement. No reference notebook is available to confirm it matches the intended
research model, so it is marked `RESEARCHER DECISION REQUIRED (model fidelity)`
even though it is internally consistent and fully testable.

### 2.3 Opponent B scenarios (verified)
- **B1 random**: `random.Random(810043).sample(all_nodes, 50)`; K-prefix.
- **B2 degree**: top-50 by out-degree descending, node ID ascending; K-prefix.
- **B3 positive PageRank**: PageRank on the positive-only directed subgraph
  (edge weight = transmission probability, α=0.85, tol=1e-10, max_iter=200),
  top-50 descending, node ID ascending; K-prefix.
- **B4 community-concentrated**: Louvain on the undirected, unweighted projection
  (signs ignored), seed 42; take the largest community (ties by smallest node ID;
  size 227), sort by out-degree descending, node ID ascending; K-prefix.
- All four orders are **nested across K** (B seed set for K is a prefix of the
  K=50 list). All orders are ≥ 50 for every scenario on this network; candidate
  pools always reached exactly 10·K and never contained a B seed.

### 2.4 Candidate pool (verified)
- Size target 10·K (reached exactly for every K here).
- Candidate score = Σ probabilities of outgoing **positive** edges minus
  Σ probabilities of outgoing **negative** edges. Negative relationships are
  never added to the influence score (polarity-aware).
- 70 % ranked / 30 % random: `n_ranked = int(0.7 * 10K)`, random part sampled
  without replacement from remaining non-B nodes. B seeds excluded everywhere.
- The pool is a *node-level* score only (does not use target in-degree or
  distance); documented as the starter's design.

### 2.5 SSA (verified)
Discrete set-based SSA: population 12, iterations 10, mutation 0.20,
`c1 = 2·exp(-(4t/T)²)`, exploitation probability `1 − c1/2`; leader cells are
drawn from food → current salp → pool; followers copy positions from the previous
salp with 1..K random positions, then mutate; best-so-far is preserved (elitism,
worst individual replaced by food). Fitness = mean objective over 15 Monte Carlo
runs with fixed common random seeds. Solutions always repaired to exactly K unique
candidate nodes not in B.

Note: this is a discrete adaptation of SSA, not the continuous canonical
equations. No reference implementation is available to confirm equation-level
fidelity → `RESEARCHER DECISION REQUIRED (SSA fidelity)`. It is not replaced.

### 2.7 Blocked_B
- The starter's **only** implementation is in `scenario_runner.py`:
  `Blocked_B = max(0, mean_s Spread_B(∅, B, s) − mean_s Spread_B(A, B, s))`,
  where the baseline runs A = ∅ with the same B seeds and the **same Monte Carlo
  seeds** (paired/common random numbers), averaged over the evaluation seeds.
- The dead helper `metric_cache_eval` in `experiment_core.py` references
  `m["blocked_B"]` but never computes it (latent `KeyError`).
- No reference notebook exists to confirm this is the intended research
  definition. The master prompt explicitly forbids merely assuming
  `baseline − Spread_B`. Therefore:
  **Blocked_B is implemented as an explicit, reproducible protocol but its
  scientific validity is `RESEARCHER DECISION REQUIRED`.**
- Experiment impact: O2 is fully validated and independent of Blocked_B.
  O1, O3, O4, O5, O6 are run and stored with
  `objective_validity = provisional_blocked_b` and are reported separately; they
  are never presented as a validated six-objective result.

### 2.8 Modes and budget
- SSA-only and SSA+Swap both start from the **same saved SSA seed set**.
- Swap: sampled one-for-one replacements, at most `max_tests = 100` evaluated
  pairs (all pairs when fewer), applies the **single best improving** swap.
  Elitist (never accepts equal/worse); exactly K unique candidates; B excluded.
  The starter comments claim this matches the (missing) source notebook, so the
  single-acceptance policy is preserved. `RESEARCHER DECISION REQUIRED` if the
  intended refinement is iterative; this is documented rather than changed.
- Planned configurations: 4 scenarios × 5 K × 6 objectives × 2 modes = 240.

## 4. Scientific risks and decisions

1. **Missing reference notebooks** — all "verify against source" items cannot be
   verified. This is the single largest limitation. Documented everywhere.
2. **Blocked_B definition** — provisional, as described in §2.7. O2 is the only
   fully validated objective. Primary comparative conclusions must use O2 /
   final Net Advantage; other objectives are exploratory.
3. **SSA fidelity** — discrete adaptation, equations preserved from starter;
   canonical-equation fidelity unverified.
4. **Swap policy** — single accepted best swap per 100 tested pairs (starter
   behavior), not iterative refinement.
5. **Network density/reciprocity** — 7500 arcs over 1000 nodes, average degree
   ~15, only 4 reciprocal arcs because each underlying pair is oriented once.
   Real signed social networks are sparser and more reciprocal; external validity
   is limited. Preserved as designed.
6. **Statistical unit** — one optimizer run per configuration. 100 common MC
   seeds give uncertainty of the *evaluation* mean, not of optimizer
   stochasticity. Between-optimizer-run variance is NOT estimated; no
   significance claim will treat MC replicates as independent optimizer runs.
7. **Common random numbers** — fixed evaluation seed list shared across all
   configurations and scenarios. This enables paired comparisons; it also means
   MC errors are correlated across configurations (by design).
